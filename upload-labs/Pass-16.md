# Pass-16 二次渲染绕过

## 一、关卡说明

服务端对上传的图片使用 GD 库重新生成（二次渲染），剥离了原文件中附加的恶意代码。需要在渲染后仍能保留的位置嵌入 PHP 代码。

## 二、原理说明

```php
$im = imagecreatefromjpeg($upload_file);
imagejpeg($im, $upload_file);
```

重新编码时，只保留像素数据，文件头之后的附加内容 **全部丢失** 。

绕过思路：把 PHP 代码写到 **渲染后仍会被保留的数据区域** ，例如：

-  **GIF** ：调色板或图像块之间的注释区，GD 渲染时部分保留
-  **PNG** ：IDAT 块之间的 `tEXt` 块或索引颜色的冗余位
-  **JPEG** ：注释段（COM）通常会被丢弃，难度最大

## 三、绕过步骤

1. 上传一张正常 GIF 图片，让服务端完成一次二次渲染
2. 下载渲染后的图片（记为 `render.gif`）
3. 用 Hex 编辑器对比原始图片和渲染后图片，找到 **渲染后依然保留的字节位置** 
4. 在这些位置插入 PHP 木马代码，保存为 `shell.gif`
5. 重新上传，渲染后代码依然存在
6. 配合文件包含或 `.htaccess` 执行

常用工具：网上有现成的 `gif_png_jpg` 二次渲染绕过脚本，原理就是自动定位可插入点。

## 四、验证

包含执行 `shell.gif`，PHP 代码运行成功。

## 五、防御建议

1. 二次渲染后仍要检查文件内容中是否包含 `<?php`、`eval`、`system` 等危险函数
2. 上传目录禁止脚本执行，这是最有效的手段
3. 图片存储在独立域名或对象存储，与站点隔离
